# docs/api/asyncapi-workflow.md

## Purpose

Documents the full lifecycle of the async (event-driven) contract: how `asyncapi.yaml` is authored from per-section source documents, split into a full and a public bundle, validated, and turned into generated TypeScript types. It exists so contributors understand *where to edit*, *why the split is by section*, and *what is enforced in CI* without reverse-engineering the scripts.

## Key elements

- **Two bundles** — `asyncapi.yaml` (all channels) and `asyncapi.public.yaml` (SSE/observability only). The split is controlled by `SHARED_SECTIONS` in `scripts/contracts/asyncapi-bundles.ts`.
- **Section source documents** — `src/modules/observability/asyncapi.yaml` (SSE), `shared/contracts/asyncapi.workers.yaml` (RabbitMQ queues), `shared/contracts/asyncapi.root.yaml` (metadata only). The root `asyncapi.yaml` is a *merge*, never hand-edited.
- **`scripts/contracts/asyncapi-bundles.ts`** — the merge script. Copies four maps (info, channels, messages, schemas) and refuses collisions. Explicitly not `asyncapi bundle`.
- **`scripts/generate-asyncapi-types.ts`** — generates `src/types/asyncapi.generated.ts` (payload interfaces + `WORKER_CHANNELS` / `OBSERVABILITY_CHANNELS` constants). Byte-identical to the frontend's copy; inputs differ.
- **RabbitMQ queue channels** — `worker.email.send`, `worker.pdf.generate`. Queue-name strings are exported from the generated constants; no hand-written duplicates.
- **CI / local commands** — `lint:asyncapi`, `gen:asyncapi`, `docs:asyncapi`, `contracts:bundle`, `check:contracts-bundle`, `lint:asyncapi:modules`.
- **`asyncapi.generated.ts` is gitignored** — regenerated by `postinstall` and a pre-commit hook; no staleness check needed.

## Notes

- The merge is a **copy of four maps**, not `asyncapi bundle` (which would inline `$ref`s and break the type generator). The script header carries the full reasoning.
- `asyncapi.public.yaml` is the **only** bundle in `SHARED_FILES`; `asyncapi.yaml` is `shared: false` and not identity-checked.
- The generated `.ts` output is **deliberately excluded** from spec-identity checks: it is gitignored, regenerated before anything runs, and the two repos' outputs are *meant* to differ.
- Worker queue payloads use `additionalProperties: false` so that `JSON.stringify` round-trips exactly — a wider local type would silently break when the broker is enabled.
- Channel names must cross a real process boundary (SSE frame, AMQP message). In-process-only events are not channels and should not be declared here.
