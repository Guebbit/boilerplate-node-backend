# public/images/seed/README.md

## Purpose

Documents the committed seed-fixture images that the demo seeders (`db/demo/index.ts`) reference by name. It exists to explain *why* this subdirectory is the one exception to the `.gitignore` rule for `public/images/`, and how to regenerate the fixtures when catalogue roles change.

## Key elements

- **`/images/seed/<name>.jpg`** — the original fixture photos, served by the `express.static` mount in `src/app.ts`.
- **`/images/seed/thumbs/v1/<name>.webp`** — thumbnails generated by the same pipeline as real uploads (`@infrastructure/adapters/image`), rooted under `seed/` to stay inside the single committed directory.
- **`demo-images.generated.json`** (in `src/modules/products/` and `src/modules/users/`) — mapping files written by the generator script; read by `demo.ts` / `demo-catalog.ts` to attach an image to each seeded row.
- **`scripts/generate-seed-images.ts`** (`npm run seed:images`) — downloads one real photo per catalogue role and runs it through the standard digest/thumbnail pipeline. Never hand-placed or hot-linked.

## Relationships

No dependency-graph neighbors. The README documents logical references to `db/demo/index.ts`, `src/app.ts`, `src/infrastructure/adapters/storage.ts` (`resolveUploadDestination`), `IMAGE_PIPELINE_PLAN.md`, and the two `demo-images.generated.json` files, but none appear as graph edges to this file.

## Notes

- **Re-generation sequence:** after changing catalogue roles, run `npm run seed:images` *then* `npm run seed:export`. Skipping either step leaves seeders pointing at stale or missing image names.
- **`.gitignore` boundary:** everything under `public/images/` is ignored *except* this `seed/` subdirectory. That is the sole reason the subdirectory exists — it lets one blanket ignore rule cover runtime uploads without enumerating fixture names.
- **Not runtime data:** these images are repository content, not written by `resolveUploadDestination`. Do not treat them the same way as files under `public/images/` directly.
