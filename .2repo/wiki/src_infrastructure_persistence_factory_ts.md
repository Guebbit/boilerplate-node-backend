# src/infrastructure/persistence/factory.ts

## Purpose

Shared primitives that every module's `factory.ts` would otherwise duplicate: identity handling (`_id`, `createdAt`, `updatedAt`), the overrides-bag type, and small helpers for date/undefined normalisation. Lives in `infrastructure` because it knows a document has an `_id` but nothing about what the document means.

## Key elements

- **`FactoryIdentity`** — interface for the three identity fields every factory accepts (`id?`, `createdAt?`, `updatedAt?`), where dates are `Date | string`.
- **`OverridesFor<TEntity>`** — generic type that derives a factory's overrides bag from its contract entity (the Orval-generated model), swapping the four date/id fields with `FactoryIdentity` semantics. Prevents hand-written field lists from drifting from `openapi.yaml`.
- **`compact(source)`** — strips keys whose value is `undefined` so a caller's "I did not say" does not shadow a model default.
- **`toDate(value)`** — `Date | string | undefined` → `Date | undefined`; passes `undefined` through unchanged.
- **`toObjectId(id?)`** — `undefined` → fresh `Types.ObjectId`; string → pinned one.
- **`identityOf(identity)`** — produces `{ _id, createdAt, updatedAt }` for a fixture. An unstated `createdAt` is extracted from the ObjectId's leading 4-byte timestamp; `updatedAt` defaults to `createdAt` unless explicitly stated.

## Relationships

Consumed by every module factory that builds Mongoose documents:

- `src/modules/account/factory.ts`
- `src/modules/cart/factory.ts`
- `src/modules/locales/factory.ts`
- `src/modules/orders/factory.ts`
- `src/modules/products/factory.ts`
- `src/modules/users/factory.ts`
- `src/modules/wishlist/factory.ts`

Each imports `OverridesFor`, `identityOf`, `compact`, `toDate`, and/or `toObjectId` to construct its entity fixture without restating the identity plumbing.

## Notes

- **Timestamps are pinned, not generated by Mongoose.** The seed export saves with `{ timestamps: false }`; a "whenever the export ran" `createdAt` would make the artefact permanently stale. Fixtures state their own dates.
- **No ordering guarantee.** This file does not ensure `createdAt ≤ updatedAt` or any relational date logic. A test that cares about ordering must pass its own dates.
- **Second-granularity.** `ObjectId.getTimestamp()` is second-precision, so fixtures created in the same tick share an exact `createdAt`. Tests that sort or paginate on that field must supply distinct dates.
- **`deletedAt` is widened** in `OverridesFor` to `Date | string | undefined` (it is not part of `FactoryIdentity`) so it remains either present or absent—never present-and-undefined—after `compact`.
