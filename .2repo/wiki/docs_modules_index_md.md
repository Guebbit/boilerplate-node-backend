# docs/modules/index.md

## Purpose

Index and orientation page for the modules documentation section. It defines the vertical (domain) vs. horizontal (mechanism) split of the wiki, renders the module dependency graph, lists every module with a one-line description grouped by subdomain (core / supporting / generic), and documents the frontend–backend module pairing asymmetry. It exists so a reader can pick the right domain page without opening any of them.

## Key elements

- **Module dependency graph** (mermaid flowchart + table between `<!-- module-graph:start -->` and `<!-- module-graph:end -->` markers) — generated by `npm run docs:graph` from `dependency-cruiser` output; `check:docs-graph` fails CI if it drifts.
- **"Every module" list** — each module gets a link, a one-line description, and a "Deeper:" pointer to a sub-page where applicable (e.g. cart → cart-checkout, inventory → inventory-reservations, payments → payments-provider-port, account → account-sessions).
- **Subdomain grouping** — modules are labelled core (cart, orders, products), supporting (delivery, inventory, payments, wishlist), or generic (account, audit-logs, feedback, locales, observability, users), per the Strategic DDD theory page.
- **"The two repositories" table** — maps each backend module to its frontend counterpart in `boilerplate-vue-frontend`; flags `audit-logs`→`admin` and `observability`→`admin`+`realtime` as intentional asymmetries. Enforced by `tests/cross-cutting/frontend-pairing.test.ts`.
- **Invisible-coupling warning** — prose callout listing three non-import couplings (shared DB document, string-keyed metrics, TTL-index retention) that the generated graph cannot show.

## Relationships

- Links **to** every sibling module page in `docs/modules/` (`account.md`, `cart.md`, `orders.md`, `inventory.md`, `payments.md`, `delivery.md`, `feedback.md`, `locales.md`, `observability.md`, `audit-logs.md`) as its primary content; those pages are the "deeper" targets.
- Links to sub-pages `cart-checkout.md`, `inventory-reservations.md`, `payments-provider-port.md`, and `account-sessions.md` as the "Deeper:" follow-ups.
- Links **out** to `docs/api/endpoints.md` (the single route table) and to `docs/theory/`, `docs/tools/`, `docs/reference/` for the horizontal-cut content this page explicitly does not own.
- Is referenced **by** the module pages themselves (each links back to this index as its parent section), but no module page imports code from this file.

## Notes

- The graph block is machine-generated; do not hand-edit between the markers. Only prose outside the markers is authored.
- `feedback` and `locales` appear as isolated nodes (no imports in or out); the page calls this out explicitly so a reader does not assume a missing edge is a bug.
- The "one-rule" convention: a module page owns a *decision*, a tools page owns a *mechanism*. If you find content that blurs the line, it belongs on the wrong page.
- The frontend pairing test means adding a module here without a corresponding entry in `tests/cross-cutting/frontend-pairing.test.ts` will fail CI.
