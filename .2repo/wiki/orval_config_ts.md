# orval.config.ts

## Purpose

Orval build configuration that generates TypeScript model interfaces and Zod schema validators from the project's OpenAPI specification. It exists so that `api/models/` and `api/schemas.zod.ts` stay in sync with `openapi.yaml` without hand-writing types.

## Key elements

- **`zodSchemas`** – the single Orval project block (named arbitrarily; the name is not meaningful to Orval).
  - `input: './openapi.yaml'` – the OpenAPI document to parse.
  - `output.mode: 'single'` – all generated operation code lands in one file.
  - `output.target: './api/schemas.zod.ts'` – where Zod validators + operation stubs are written.
  - `output.schemas: './api/models'` – directory for raw TS interfaces (models).
  - `output.client: 'zod'` – emit only Zod schemas/types; **no** HTTP-client call functions are generated.
- **`defineConfig`** (imported from `orval`) – wraps the config object so Orval's CLI can type-check it.

## Relationships

- **`openapi.yaml`** – direct input; every change here alters the generated output.
- **`api/schemas.zod.ts`** – direct output target; contains the generated Zod schemas and (in `'zod'` client mode) no HTTP call helpers.
- **`api/models/`** – direct output directory; receives the generated TS interfaces for all OpenAPI schemas/components.
- **`docs/reference/root.md`** – references the generated types/schemas as the canonical API contract for documentation; not a build dependency.

## Notes

- The `client` value is deliberately `'zod'`. This project is a backend that only *consumes* the generated types and validators (e.g. `@api/models`, `@api/schemas.zod`); there is no in-repo code that calls an HTTP client generated by Orval. Switching to `'fetch'`, `'axios'`, `'react-query'`, etc. would produce unused call functions.
- `mode: 'single'` keeps all generated operation code in one file. If the OpenAPI spec grows large, `'tags'` or `'tags-split'` would fan it out per tag.
- The config exports a single default object; there is no multi-project array. Add sibling keys to `defineConfig` if a second spec or output target is ever needed.
