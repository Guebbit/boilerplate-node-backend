# tests/integration/product-multipart-write.test.ts

## Purpose

Integration test that writes and updates a product via `multipart/form-data` (the only way to attach an image) and verifies the server correctly decodes string-typed form fields — `price` as a number and `active` as a boolean — before they reach the Zod schema. No other suite exercises this combination, because JSON-path suites already send typed values and the upload-security suite has no numeric field.

## Key elements

- **`PNG_BYTES`** — a 4×4 real PNG generated by `sharp` in `beforeAll`. Must be fully decodable (not a magic-byte stub) because the upload pipeline runs `sharp` inline.
- **`uploadedFiles()`** — helper that lists files (excluding subdirectories like `thumbs/`) in `UPLOAD_DIRECTORY`; used by the cleanup logic.
- **`beforeEach` / `afterEach` cleanup** — snapshots the upload directory before each test and removes any newly-created files after, preventing fixture accumulation.
- **Test: "creates a product, decoding the string-transported price"** — `POST /products` with `.field('price', '101.5')` + `.attach('imageUpload', …)`; asserts `201` and that the persisted `price` is the number `101.5`, not the string `'101.5'`.
- **Test: "updates a product, decoding the string-transported price"** — `PUT /products/:id` with a string price; asserts `200` and numeric `price === 42`.
- **Test: "decodes the boolean alongside the number"** — sends `active: 'false'` (a truthy string); asserts the stored value is `false`, not `true`.
- **Test: "defaults active to true when the form omits it"** — omits `active` entirely; asserts stored value is `true`.
- **Test: "still rejects a price that is not a number at all"** — sends `price: 'not-a-number'`; asserts `422` and that no file is left behind in the upload directory.

## Relationships

- **`tests/support/http.ts`** — provides `api()` (the supertest-style HTTP client) and `authenticateAs('admin')` for bearer-token auth on every request.
- **`tests/support/setup-test-db.ts`** — `setupTestDb()` resets the database before the suite runs so each test starts from a known state.

## Notes

- The multipart body carries **no types**: every field arrives as a string. The server's `readInput` decoder (`numbers`/`booleans`) is the sole mechanism that converts `'101.5'` → `101.5` and `'false'` → `false` before Zod validates. If that decoder is removed or misconfigured, every multipart write with a file will 422 (or worse, persist a truthy string as a boolean).
- The PNG fixture must be a *genuinely decodable* image. A header-only stub will pass the magic-byte check but crash `sharp` during inline digest generation.
- File cleanup intentionally targets **files only**; the `thumbs/` subdirectory created by the digest pipeline is left in place (it is a persistent derivative, not a per-test artifact).
- Assertions read `response.body.data.price` / `.active` (the persisted document), not just the HTTP status, because a `200` that silently stored `'101.5'` would be indistinguishable from success by status alone.
