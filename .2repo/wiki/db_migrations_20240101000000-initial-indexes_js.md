# db/migrations/20240101000000-initial-indexes.js

## Purpose

Bootstrap migration that creates the initial set of MongoDB indexes across the `users`, `products`, and `orders` collections. It has already run against every existing database and is kept as-written for historical fidelity; new index needs are declared on their respective schemas instead.

## Key elements

- **`up(db)`** — Creates seven indexes in parallel via `Promise.all`:
  - `users_email` (`{ email: 1 }`, **unique**) — enforces one registration per address.
  - `users_tokens_token` (`{ 'tokens.token': 1 }`) — refresh-token / reset / delete lookups.
  - `users_deletedAt` (`{ deletedAt: 1 }`) — soft-delete filter for admin search.
  - `products_createdAt` (`{ createdAt: -1 }`) — default listing sort.
  - `products_active_deletedAt` (`{ active: 1, deletedAt: 1 }`) — storefront filter.
  - `orders_userId_createdAt` (`{ userId: 1, createdAt: -1 }`) — "my orders" newest-first.
  - `orders_email` (`{ email: 1 }`) — order lookup by email.
- **`down(db)`** — Drops all seven indexes sequentially; each `dropIndex` is wrapped in a try/catch so a missing index does not abort the rollback.

## Notes

- **Do not edit this file to change index definitions.** Databases that have already run it will not re-execute it. For scratch databases it must match the schema's index block (e.g. `src/models/users.ts`); a mismatch is caught by `tests/unit/db/migration-model-indexes.test.ts`.
- **Index names are load-bearing.** Mongo rejects a createIndex call whose name is already held by an index with a different key spec. The app re-declares these same names at startup, so renaming here causes a runtime conflict.
- **`users_email` carries `unique: true`** even though the rest of the file is "as-written." Omitting it would trigger `IndexOptionsConflict` whenever a later migration or app-startup tries to create the non-unique version. The unique constraint is also enforced by `20260808200000-users-email-unique.js` for existing databases.
- **`createIndex` is idempotent only when name, key spec, *and* options all match.** Same name + same key + different options is an error, not a no-op.
- Demo/seed data is owned by `npm run db:seed`, not by this migration.
