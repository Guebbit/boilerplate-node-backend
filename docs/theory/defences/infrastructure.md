# Infrastructure, configuration and deployment

Nothing here is a coding mistake. Every row is something that was **left as it shipped**, or
configured once by someone who has since moved on. That is what makes the family dangerous: a
misconfiguration has no author, produces no error, and passes every test.

The strategy this repo takes: **a dangerous default should stop the boot, not warn in a log nobody
reads.**

## A boot that refuses

| Attack                          | How it works                                       | This boilerplate                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Security misconfiguration       | debug on, sample apps, permissive ACLs left as-is  | The app refuses to start if `NODE_TOKEN_ACCESS` / `NODE_TOKEN_REFRESH` / `NODE_TOTP_ENCRYPTION_KEY` / `NODE_METRICS_TOKEN` are unset, too short, or still the shipped placeholder; also on a missing `NODE_URL`, a production `NODE_CORS_ORIGIN` left at its localhost default, and an SMTP host configured without its credentials — `kernel/required-config.ts`, each module's `requiredConfig` |
| Insecure defaults of frameworks | CORS `*`, introspection on, `trust proxy` true     | An explicit origin allowlist, never `*` — load-bearing, because the frontend sends every request with `withCredentials: true`, which a browser refuses to honour against a wildcard. And `trust proxy` is a hop COUNT: a misconfigured `NODE_TRUST_PROXY_HOPS` warns loudly rather than silently trusting a spoofable `X-Forwarded-For` — `app/security.ts`                                       |
| Secrets in environment / images | `.env` in the repo, `ENV` in a Dockerfile, CI logs | `.dockerignore` keeps `.git`, `.env`, coverage and reports out of the image. The seed interlock refuses production outright, and refuses everywhere else too when any seed account is still logging in with its committed, public fallback password — `scenarios/apply.ts`, `scenarios/accounts.ts`                                                                                               |
| Time / clock drift              | token expiry and log ordering become unreliable    | The TOTP window tolerance absorbs small drift — `account/two-factor/totp.ts`. NTP on the host is the deployment's: [Clock](../../tools/deployment-hardening.md#clock).                                                                                                                                                                                                                            |

## Headers the browser acts on

Set once, globally, because a header applied per-route is a header someone will forget.

| Attack                   | How it works                                                               | This boilerplate                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------ | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Missing security headers | no CSP, HSTS, `X-Content-Type-Options`, frame-ancestors, `Referrer-Policy` | `helmet()`, applied globally, with its defaults taken rather than pared down: a default CSP (`default-src 'self'`, `object-src 'none'`, `frame-ancestors 'self'`), HSTS, `nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: no-referrer`, `X-XSS-Protection: 0` (the legacy filter was itself a vulnerability), and `X-Powered-By` removed — `app/security.ts`. The CSP that actually governs script is the frontend static server's, over HTML this app never serves. |
| Permissive CORS          | a reflected `Origin`, `null` allowed, or a wildcard with credentials       | The explicit allowlist above. Non-browser callers (no `Origin` at all — curl, healthchecks) are allowed through, which is not a weakening: CORS governs what a BROWSER may read, and a browser always sends one.                                                                                                                                                                                                                                                                |

## The container and the image

| Attack                         | How it works                                                 | This boilerplate                                                                                                                                                                                                               |
| ------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Container running as root      | an escape becomes host root                                  | The production image drops to the `node` user after the last `apk`/`npm` step, and `--ignore-scripts` keeps a transitive `postinstall` from running at build time — `docker/Dockerfile.production`                             |
| Container escape               | kernel bugs, a mounted Docker socket, host paths             | No Docker socket is mounted and no privileged flag is set — `docker-compose.production.yml`                                                                                                                                    |
| Base-image vulnerabilities     | outdated OS packages baked into the image                    | Pinned to `node:25-alpine` by MAJOR only, so a rebuild picks up patches — and only a rebuild does — `docker/Dockerfile.production`                                                                                             |
| Exposed management interfaces  | database UIs, dashboards, container APIs, SSH with passwords | No management UI is shipped in the production compose file — see [Data layer](data-layer.md#reaching-the-store), and [Network segmentation](../../tools/deployment-hardening.md#network-segmentation) for keeping it that way. |
| Unnecessary services and ports | leftover daemons                                             | The production compose file publishes one port, bound to loopback — `docker-compose.production.yml`                                                                                                                            |

## The network and the platform

Rows this repo cannot close from inside a container. Naming the owner is the verdict.

| Attack                                  | How it works                                          | Owner, and what this repo does about it                                                                                                                                                                                                                                                             |
| --------------------------------------- | ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No WAF / rate limiting at the edge      | every request reaches the app                         | Partly closed here: a global per-address burst brake plus credential-specific budgets — `infrastructure/http/middlewares/rate-limit.ts`. The edge half, and the hop-count trap that comes with adding one, is [Edge rate limiting](../../tools/deployment-hardening.md#edge-rate-limiting-and-waf). |
| Lack of network segmentation            | a flat network; the DB reachable from anything        | The compose network IS the segmentation: only the app is published, and only to loopback. What a deployment adds on top — host firewall, bastion, no published DB UI — is [Network segmentation](../../tools/deployment-hardening.md#network-segmentation).                                         |
| Missing egress controls                 | a compromised host phones home freely                 | The deployment's — recipe at [Egress filtering and cloud metadata](../../tools/deployment-hardening.md#egress-filtering-and-cloud-metadata). Worth pairing with [SSRF](ssrf.md): default-deny egress is practical here precisely because the outbound allowlist is three hosts.                     |
| Over-permissive cloud IAM               | wildcard policies, long-lived keys                    | The deployment's. This app needs no cloud credential to run.                                                                                                                                                                                                                                        |
| Public object storage                   | a bucket readable or writable by the world            | No object storage is used: uploads are local, behind `app/static-assets.ts`. A deployment that adds a bucket gets the rules at [Object storage for uploads](../../tools/deployment-hardening.md#object-storage-for-uploads).                                                                        |
| Subdomain takeover                      | a dangling CNAME to a deleted cloud resource          | DNS, and the domain owner.                                                                                                                                                                                                                                                                          |
| DNS hijacking / registrar compromise    | the domain itself is stolen                           | The registrar account's owner.                                                                                                                                                                                                                                                                      |
| Exposed Kubernetes / orchestration APIs | dashboard, kubelet or etcd without auth               | The platform's. No k8s manifests ship in this repo.                                                                                                                                                                                                                                                 |
| Exposed CI/CD                           | a runner with cloud credentials; PR-triggered secrets | GitHub Actions with no deployment credentials in the workflows — `.github/workflows/ci.yml`.                                                                                                                                                                                                        |
| Infrastructure-as-code drift            | manual hotfixes reopen closed holes                   | The compose files are the declaration; nothing here can stop a hand-edit on a server.                                                                                                                                                                                                               |
| Backup and disaster-recovery gaps       | ransomware or deletion is final                       | [Backups](../../tools/backups.md) — resticprofile, and the reminder that an untested restore is not a backup. Summarised at [Backups and tested restore](../../tools/deployment-hardening.md#backups-and-tested-restore).                                                                           |

## Seeing it happen

A control nobody can observe is a control nobody can trust.

| Attack                              | How it works                               | This boilerplate                                                                                                                                                                                                                                                                                               |
| ----------------------------------- | ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Insufficient logging and monitoring | no audit trail, no alerts, logs unretained | Every 429 logs at `warn`, audited or not — the limiters mount BEFORE the request logger, so a refusal short-circuits ahead of the only thing that would otherwise record it — `rate-limit.ts#refuse`. Auditable actions are registered and asserted by `tests/cross-cutting/audit-actions-registered.test.ts`. |
| Tamperable audit logs               | a writable log store with no integrity     | Logs are append-only to stdout from this process's side; integrity at the collector is the deployment's.                                                                                                                                                                                                       |
| Outdated / vulnerable components    | no patch process, pinned old versions      | See [Supply chain](supply-chain.md).                                                                                                                                                                                                                                                                           |
