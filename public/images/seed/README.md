# Seed fixture images

The demo images `db/demo/index.ts` points its products and users at. They are **repository
content**, not runtime data: they are committed, and the seeders' `imageUrl`/`thumbnailUrl`s
reference them by name.

Generated by `npm run seed:images` (`scripts/generate-seed-images.ts`) — a real photo per
catalogue role, downloaded once and run through the same digest/thumbnail pipeline a real upload
goes through (`@infrastructure/adapters/image`), never hand-placed or hot-linked. The two
`demo-images.generated.json` files it also writes (`src/modules/products/`,
`src/modules/users/`) are what `demo.ts`/`demo-catalog.ts` read to attach an image to each row —
re-run the script, then re-run `npm run seed:export`, whenever the catalogue's roles change.

Everything else under `public/images/` is a runtime upload written by
`resolveUploadDestination` (`src/infrastructure/adapters/storage.ts`), and `.gitignore` drops it. That is
the only reason this subdirectory exists — one rule can then ignore uploads without needing to
enumerate which files are fixtures, and adding a fixture does not mean editing `.gitignore`.

Referenced as `/images/seed/<name>.jpg`, served by the `express.static` mount in `src/app.ts`.
Thumbnails live one level down, at `/images/seed/thumbs/v1/<name>.webp` — the same `thumbs/v1/`
naming the real upload pipeline uses (`IMAGE_PIPELINE_PLAN.md`), just rooted under `seed/` instead
of `images/` directly, so both the originals and their thumbnails stay inside the one directory
`.gitignore` already commits.
