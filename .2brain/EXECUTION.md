## Container Runtime
Everything here runs through `docker compose` / `podman compose` — there is no bare-metal `pip install` path for the pipeline itself.

### `docker-compose.yml`

Run pattern: `docker compose -f docker-compose.yml run --rm <service> <command>` (or `podman compose`, per `CONTAINER_ENGINE` in `.env`) — this is the actual entry point, not a direct interpreter invocation.

Exception: the `2brain` CLI wrapper runs `query` and `check` directly on the host (pure stdlib, no container) unless `--host`/`--container` or `REPO_MODE` forces otherwise — every other subcommand still goes through the pattern above.
