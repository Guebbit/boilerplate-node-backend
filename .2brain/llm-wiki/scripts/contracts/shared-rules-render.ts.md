# scripts/contracts/shared-rules-render.ts

## Purpose
The pure half of the shared-rules code generator. It takes a parsed rules document (from YAML) and a `GenerateSpec`, and returns the text of a generated TypeScript module. It does no filesystem I/O, so tests can call it directly. Prettier formatting happens later, outside this file.

## Key elements
- **`deriveKey(value)`** (exported): turns a wire string into a constant key by uppercasing and replacing `.` with `_`. For example, `security.api_key.revoked` becomes `SECURITY_API_KEY_REVOKED`.
- **`renderGenerated(source, spec, document)`** (exported): builds the whole module. It starts with a `@module` header saying the file is GENERATED by `npm run regenerate` from the given YAML path and must not be edited. It then adds one block per entry in `spec.exports`.
- **`renderExport`** (internal): emits a docblock and an `export const <exportName> = ...;` for one `GeneratedExport`. The `keyed-list` shape goes through `renderKeyed`. Any other shape is written as `JSON.stringify` with 4-space indent, numeric separators and `as const`.
- **`renderKeyed`** (internal): writes an object literal with one docblock per key. Each key is `deriveKey(entry.value)` and each value is the JSON-quoted `entry.value`. It throws if two values derive the same key.
- **`sliceOf`** (internal): picks `document[field]`, or the whole document when `field` is undefined. It throws if the document is not an object or lacks the field.
- **`withNumericSeparators`** (internal): groups integers of five or more digits in threes (`300000` becomes `300_000`) to satisfy `unicorn/numeric-separators-style`. It skips string literals.
- **`docblock`** (internal): produces a one-line or multi-line `/** */` comment with an optional indent.

## Relationships
- Imports the `GeneratedExport`, `GenerateSpec` and `KeyedEntry` types from `src/infrastructure/config/shared-rules/generate-spec.ts`, which defines what to render.
- `scripts/contracts/generate-shared-rule-schemas.ts` is the schema-checking side. The code comment says the shape check of keyed entries lives there, and `renderKeyed` only checks for duplicate keys.
- `tests/unit/scripts/contracts/shared-rules-render.test.ts` is the unit test for this module.
- The other graph neighbors (`scripts/scaffold/plan.ts`, the altcha adapter and its tests, `tests/support/altcha.ts`, `span-scrub.test.ts`) have no visible interaction in this file's code.

## Notes
- The renderer assumes the document has already passed schema validation. `renderExport` casts the slice to `KeyedEntry[]` without checking it.
- The `numeric-separators` regex works on the JSON text and skips quoted strings. It still matches bare integers of five or more digits anywhere else in that text.
- Output is not Prettier-formatted ("before Prettier"), so formatting is done by a later step.
