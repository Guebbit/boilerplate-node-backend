# openapi.yaml

## Purpose

A **generated** OpenAPI 3.1.0 document that serves as the single, stable API contract for the Boilerplate API. It is the source for client/server codegen, SDK generation, and contract testing. It does not hand-author endpoint behavior; it is the output of a bundling step that merges a root spec with per-module specs.

## Key elements

- **Generation header** — `# Code generated by npm run contracts:bundle. DO NOT EDIT.` Sourced from `shared/contracts/openapi.root.yaml` + `src/modules/*/openapi.yaml`.
- **`info.description`** — A long normative paragraph that is effectively the contract for cross-cutting concerns: `Accept-Language` selection/fallback rules, the success-response shape rules (2xx resource, `{items, meta}` pagination, 204 empty, 201 + `Location`), and the RFC 9457 `application/problem+json` error format (including 404/405 answers that no operation declares).
- **`servers`** — Two entries: `http://localhost:3000` (Local) and `https://api.example.com` (Production).
- **`tags`** — ~25 domain tags (System, Locales, Auth, Account, Products, Cart, Orders, Payments, Invoicing, Delivery, Returns, Inventory, Webhooks, ApiKeys, etc.) that group every operation by business area.
- **`paths`** — Full endpoint definitions. Visible operations include `GET /` (health ping), `GET /livez`, `GET /readyz`, `GET /.well-known/security.txt`, `GET /locales`, and many more (truncated in this listing). Each carries `operationId`, `security`, `responses`, and `$ref`-based schemas.
- **`components`** (referenced, not fully shown) — Shared schemas (`HealthPing`, `PaginationMeta`, etc.), responses (`TooManyRequests`, `InternalError`, `ServiceUnavailable`, `NotFound`), and security schemes (`bearerAuth`, `cookieAuth`).

## Relationships

- **`github/workflows/schemathesis.yml`** — CI workflow that runs Schemathesis (a property-based OpenAPI tester) against this file. The spec is the sole input contract for that pipeline; changes here directly alter what the workflow validates.

## Notes

- **Do not edit by hand.** All changes go through the per-module source files (`src/modules/*/openapi.yaml` or `shared/contracts/openapi.root.yaml`) and are re-bundled via `npm run contracts:bundle`.
- **`Accept-Language` is deliberately absent from per-operation parameters.** The spec's `info.description` states that clients set it once in an interceptor; re-declaring it on every operation would add a redundant parameter to every generated function. The paragraph in `info.description` *is* the contract for that header.
- **Error format is fixed to RFC 9457** (`application/problem+json`) regardless of the `Accept` header. Machine-readable identity is `errors[].code`; the human-readable `detail` is the translated sentence.
- **`GET /livez` vs `GET /readyz` are intentionally different.** Liveness checks nothing beyond process uptime; readiness checks DB reachability. A container `HEALTHCHECK` must point at `/livez`, not `/readyz`.
- **The `Examples` tag** is marked "Safe to delete" — it is a minimal, self-contained domain meant as a copy-paste starting point for new modules.
