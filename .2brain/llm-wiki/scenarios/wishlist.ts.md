# scenarios/wishlist.ts

## Purpose

Defines the seeded wishlist fixtures for the two demo accounts and provides the `seedWishlistsCollection` function that inserts them. It ensures only publicly visible products are saved, so the storefront's wishlist page never renders a hole caused by a soft-deleted or inactive product.

## Key elements

- **`wishlistFixtures`** (module-local) — Array of two `makeWishlist` objects: one for `SEED_ADMIN_ID` (1 product: `scratchPostOutOfStock`) and one for `SEED_USER_ID` (2 products: `dogFoodStandard`, `dogBedPremium`). No explicit `_id`; idempotency is delegated to the seed helper.
- **`seedWishlistsCollection`** (module-local) — Maps `wishlistFixtures` through `insertIfAbsentForOwner(wishlistRepository, …)` and returns `Promise<SeedOutcome[]>`.
- **`shopModule`** (exported) — `{ seed: seedWishlistsCollection }`; the single export that registers this file in the generated shop-modules table.

## Relationships

- **`scenarios/accounts.ts`** — Source of `SEED_ADMIN_ID` and `SEED_USER_ID` used as the `userId` for each fixture.
- **`scenarios/product-ids.ts`** — Source of `SEED_PRODUCT_IDS` entries that populate each wishlist's `productIds` array.
- **`src/modules/wishlist/factories.ts`** — Provides `makeWishlist`, the factory that shapes each fixture object.
- **`src/modules/wishlist/repository.ts`** — Provides `wishlistRepository`, passed to `insertIfAbsentForOwner` as the target for insertion.
- **`scenarios/seed.ts`** — Provides the `SeedOutcome` type and the `insertIfAbsentForOwner` helper that performs the upsert-keyed-on-owner logic.
- **`scenarios/shop-modules.generated.ts`** — Regenerated by `npm run regenerate`; automatically includes this file's `shopModule` export. Deleting this file removes its entry from the generated file.

## Notes

- Product selection is deliberately restricted to publicly visible items. Seeding a soft-deleted or inactive product would create a visible gap in the wishlist page that the scoping rules then refuse to fill.
- `dogFoodStandard` is intentionally chosen for the customer account because it does not appear in any of their carts, so a "move to cart" demo actually produces a visible state change.
- The `shopModule` export is the *only* thing this file exports. All other names are module-private.
