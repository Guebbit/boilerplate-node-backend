# scenarios/products.ts

## Purpose

Defines the product catalogue's seed dataset for the demo environment: seven named products that cover the edge-case branches the storefront and repositories actually exercise (soft-deleted, out-of-stock, inactive, minimal, digital), plus 128 combinatorial filler rows that make the grid look like a real pet-supply store. Also writes per-locale translation rows for every named product. Consumed by `scenarios/apply.ts` (live DB) and integration tests (throwaway DB).

## Key elements

- **`ProductCopy`** – Internal interface for per-locale product copy. `en` is required (the fallback locale); `it` is optional.
- **`NAMED_PRODUCT_COPY`** – Single source of truth for every named product's title/description in both locales, keyed by `SEED_PRODUCT_IDS`. Prevents the English string from being duplicated between the product document and the translation batch.
- **`makeUnstockedProduct(overrides)`** – Thin wrapper over `makeProduct` that forces `onHand: 0`. States once, at the call-site level, that demo stock arrives via opening receipts (see `shop-history.ts`), never via seed.
- **`namedProducts`** – Array of 7 `ProductOverrides` objects. Each row targets a specific branch: `heaterSoftDeleted` (soft-delete), `scratchPostOutOfStock` (zero stock, no receipt), `bundleInactive` (`active: false`), `barebones` (no description/categories/image), `puppyCourseDigital` (`requiresShipping: false`), plus two "normal" rows.
- **`fillerProductId`** (re-export) – Re-exported from `./products-filler` so `shop-history.ts` and other scenario files can reference a specific filler row without importing the filler module directly.
- **`seedProductsCollection`** (implied export) – The main seeding entry point that inserts named + filler products and writes translation rows via the kernel translation helpers.
- **`productImages`** (from `products-images.generated.json`) – Fixed image data for named rows; generated by `npm run scenario:images`. Filler rows cycle through a 20-image pool via `FILLER_IMAGE_ROLE_KEYS`.

## Relationships

- **`scenarios/products-filler.ts`** – Source of `FILLER_PRODUCTS`, `FILLER_IMAGE_ROLE_KEYS`, and `fillerProductId`. This file re-exports `fillerProductId` outward.
- **`scenarios/subjects.ts`** – Provides `SEED_PRODUCT_IDS`, the stable ID constants used as keys throughout.
- **`scenarios/flows/shop-history.ts`** – The file that issues the opening receipt to bring `onHand` from 0 to a real number; `scratchPostOutOfStock` is the one named row that intentionally receives *no* receipt, remaining at zero.
- **`src/modules/products/factories.ts`** – Provides `makeProduct` and the `ProductOverrides` type used to build every row.
- **`src/modules/products/repository.ts`** – `productRepository` is imported (likely for existence checks or direct insert within the seed).
- **`src/scenarios/seed.ts`** – Provides `insertIfAbsent` and `SeedOutcome` for idempotent upserts.
- **`src/kernel/translation.ts`** – Provides `planTranslations`, `writeTranslations`, `isTranslationPlan`, `isTranslationAvailable`, and the `TranslationBatch` type used to persist per-locale copy.
- **`src/infrastructure/i18n/index.ts`** – Provides `getFallbackLocale` (the `en` locale).
- **`src/types/index.ts`** – Provides the `ProductTranslationFields` type used in `ProductCopy`.

## Notes

- **Stock is never seeded.** Every named and filler row enters the DB at `onHand: 0`. Units on the shelf only appear after `shop-history.ts` runs its opening-receipt flow, so every unit has a movement record behind it.
- **`en` is the only required locale.** A product with English-only copy is a valid catalogue state; the seeder writes exactly what is present.
- **`barebones` is deliberately sparse.** No description, no categories, no `imageUrl` — it exists to catch UI code that assumes those fields are always populated.
- **Soft-deleted vs. inactive are independent.** `heaterSoftDeleted` carries `deletedAt`; `bundleInactive` carries `active: false`. `publicScope()` hides both, but they are distinct states and only one of each exists in the dataset.
- **Image sourcing is fully generated.** No image URL is hand-written. Named rows read from `products-images.generated.json`; filler rows cycle a fixed 20-image pool, so a larger grid never triggers a new download.
- **The re-export of `fillerProductId` is intentional indirection.** It lets `shop-history.ts` and the wishlist scenario address filler rows through this file without importing `./products-filler` directly.
