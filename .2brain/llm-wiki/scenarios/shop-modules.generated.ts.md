# scenarios/shop-modules.generated.ts

## Purpose

Aggregates the `shopModule` fixture objects exported by each individual scenario file into a single named map. It is generated by `npm run regenerate` so that adding or removing a scenario file automatically updates this collection without manual edits.

## Key elements

- **`shopModuleFixtures`** (exported const) — A plain object whose keys are module names (`addresses`, `example`, `locales`, `products`, `users`, `webhooks`, `wishlist`) and whose values are the corresponding `shopModule` imports. This is the sole export of the file.

## Relationships

- **Consumes** — Imports `shopModule` from each of `addresses.ts`, `example.ts`, `locales.ts`, `products.ts`, `users.ts`, `webhooks.ts`, and `wishlist.ts`.
- **Feeds** — `shop-modules.ts` imports and types the `shopModuleFixtures` object from this file; it is the primary (likely only) consumer.

## Notes

- **Do not edit by hand.** The file header states it is regenerated by `npm run regenerate`. To add or remove a module, add or delete the corresponding source file, then run the regenerate script.
- The import alias pattern (`shopModule as <name>`) means each source file must export a symbol literally named `shopModule`; the generated file renames them to the module key.
- Object key order in `shopModuleFixtures` is fixed by generation (alphabetical by module name) and should not be reordered manually.
