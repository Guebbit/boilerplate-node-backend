# asyncapi.yaml

## Purpose

Bundled AsyncAPI 3.0.0 contract that is the single source of truth for all event-driven, real-time, and job-queue flows in the backend. It is generated by `npm run contracts:bundle` from per-module source files and is consumed by type generation (`generate-asyncapi-types.ts`), Spectral lint rules, and CI breaking-change checks.

## Key elements

- **`asyncapi` / `id` / `info`** — Spec version 3.0.0; contract version 2.0.0 (intentional breaking change to the Standard Webhooks envelope).
- **Servers** — `sseLocal` (local HTTP for SSE), `subscriberEndpoint` (variable HTTPS URL per subscription), `rabbitmqLocal` (local AMQP broker on `localhost:5672`).
- **Channels — Observability (SSE)** — `observability.metrics.snapshot`, `observability.metrics.updated`, `observability.heartbeat`; tagged `x-transport: sse` so the type generator can distinguish SSE channels from name prefixes.
- **Channels — Webhook events** — `order.created`, `order.paid`, `order.shipped`, `order.cancelled`, `payment.succeeded`, `payment.failed`, `payment.refunded`, `return.requested`, `return.received`, `return.closed`; all bound to `subscriberEndpoint`.
- **Channels — Worker job queues** — `worker.webhook.deliver`, `worker.email.send`, `worker.image.digest`; all bound to `rabbitmqLocal`.
- **Operations** — One `send` operation per channel, each carrying the message payload `$ref` and a human-readable description of when and how the event fires.

## Relationships

- **docker-compose.production.yml** — Provisions the RabbitMQ broker (port 5672) and the HTTP service (port 3000) that the `rabbitmqLocal` and `sseLocal` servers in this file point to in a local/production environment.

## Notes

- **Do not edit.** Regenerate via `npm run contracts:bundle`.
- The `x-transport: sse` extension is the sole marker the type generator uses to classify SSE channels; the `observability.` name prefix is *not* the discriminator.
- `subscriberEndpoint` uses template variables (`{subscriberHost}`, `{subscriberPath}`) because each subscription has its own URL. Spectral rules pass because channels do bind to a declared server name, even though it resolves per-subscription.
- The `info.version` bump to 2.0.0 documents the breaking envelope change for humans; the `check:asyncapi-breaking` gate compares the **spec** version (3.0.0) against `origin/main`, so the gate still reports the real break until this branch is merged.
- `order.paid` and `order.shipped` are derived from a single `order.status_changed` domain event filtered on the `to` field, not their own events.
