# tests/contract/password-set-paths.test.ts

## Purpose

Contract test that verifies **every** route which writes a password enforces the same breached-password rejection. Instead of testing the check once per module (and risking a gap when a new entry point is added), it exercises all three owner-facing paths over HTTP with one known-breached fixture, and a second "canary" block reads the bundled OpenAPI spec to assert no *other* route sets a password. Scoped system-wide because the invariant spans the contract, not a single module.

## Key elements

- **`BREACHED_PASSWORD`** (`'Password1!'`) — composition-valid password present in `shared/rules/breached-passwords.txt`; composition rules alone cannot be what rejects it.
- **`PasswordSetPath`** interface — `{ name, attempt }` shape consumed by `describe.each`; each `attempt` returns the HTTP response plus an `assertNoChange` closure proving no credential was written.
- **`signupPath` / `changePath` / `resetPath`** — the three concrete entries (POST `/account/signup`, POST `/account/password`, POST `/account/password/reset/confirm`).
- **`describe.each([…])`** block — for each path asserts 422 status and that no new row / old credential is still valid.
- **`operationsThatSetAPassword()`** — parses `openapi.yaml` (at `REPO_ROOT`) with the `yaml` library, walks every operation's `requestBody` → schema → properties, and returns the sorted list of `METHOD /route` entries whose body references a `PasswordNew` schema.
- **Canary `describe`** ("the routes that can set a password") — asserts the list is *exactly* the three owner routes; a new staff or admin route that sets a password fails until a breach-check case is added above.

## Notes

- **Two paths, one implementation.** `changePath` and `resetPath` both funnel into `account/services/password.ts#passwordChange` (`passwordChangeWithCurrent` and `completePasswordReset` are thin wrappers). The test exercises two *entry points*, not two independent rules.
- **The canary reads a bundled file, not the in-memory contract.** `openapi.yaml` is generated by `npm run contracts:bundle`; if that step is skipped or the spec is stale, the canary will fail against an outdated file rather than the live API.
- **`@tests/contract` is imported for side effects only** — no symbols are destructured from it.
- **The breached-password fixture is intentionally composition-valid** so the 422 can only come from the breach list, not from a weak-password policy.
