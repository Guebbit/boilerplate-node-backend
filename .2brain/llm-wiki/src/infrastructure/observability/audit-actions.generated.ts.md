# src/infrastructure/observability/audit-actions.generated.ts

## Purpose

Defines the set of **core audit action identifiers** for security events that fire *before* any domain logic executes (auth failures, rate-limit denials, re-auth challenges, token/key rejections). The file is generated from `shared/rules/audit-actions.yaml` by `npm run regenerate`; the YAML is the single source of truth.

## Key elements

- **`coreAuditActions`** (`as const`) — a frozen object of string-literal keys mapping human-readable names to dotted audit-action IDs:
  - `SECURITY_UNAUTHORIZED` — no usable credential on a guarded route.
  - `SECURITY_FORBIDDEN` — caller identified but lacks the required permission.
  - `SECURITY_RATE_LIMIT_HIT` — rate-limit budget exhausted.
  - `SECURITY_REAUTH_REQUIRED` — step-up re-authentication demanded (recorded because the subsequent retry looks like an ordinary success).
  - `SECURITY_TOKEN_INVALID_SIGNATURE` — bearer JWT whose signature or key fails verification (attack signal only).
  - `SECURITY_TOKEN_MALFORMED` — value is not a well-formed token of the expected kind.
  - `SECURITY_API_KEY_REVOKED` — `sk_` key with correct secret presented after revocation.

## Notes

- **Do not edit this file.** Modify `shared/rules/audit-actions.yaml` and re-run `npm run regenerate`.
- The `as const` assertion gives each property a unique literal type, so downstream code can narrow on the exact string (e.g. `'security.rate_limit_hit'`).
- Semantic distinction worth remembering: `SECURITY_TOKEN_INVALID_SIGNATURE` implies a *forged/attacked* credential (always an attack signal), whereas `SECURITY_TOKEN_MALFORMED` can also reflect an expired or revoked session held by a legitimate customer. The doc comments intentionally separate these to guide alerting and triage.
