# src/infrastructure/observability/metrics.generated.ts

## Purpose

Single source of truth for all infrastructure metric definitions (name, kind, help text, label names, and histogram buckets). The file is generated from `shared/rules/metrics.yaml` via `npm run regenerate`; the YAML is the editable artifact. Every consumer of infrastructure metrics imports the typed `infrastructureMetricData` object from here rather than hard-coding metric names, ensuring a one-place schema.

## Key elements

- **`infrastructureMetricData`** (exported `as const` object) — a flat map of ~21 metric definitions spanning HTTP, cache, outbox, security/auth, database, queue, rate-limit, process, and crontab-job concerns. Each entry carries:
  - `name` — Prometheus-style metric name (e.g. `http_requests_total`).
  - `kind` — `'counter' | 'gauge' | 'histogram'`.
  - `help` — human-readable description used in exposition.
  - `labelNames` (optional) — ordered array of label keys.
  - `buckets` (histograms only) — explicit boundary values.

## Relationships

- **metrics-http.ts** — consumes `httpRequestsTotal`, `httpRequestDuration`, `httpRequestErrorsTotal`, `httpInflightRequests` to instrument request handling.
- **metrics-cache.ts** — consumes `cacheInvalidationFailuresTotal` and `cacheRequestsTotal`.
- **metrics-outbox.ts** — consumes the four `outboxEvents*` metrics.
- **security-events.ts** — consumes `securityEventsTotal` and `staleCredentialsTotal`.
- **command-metrics.ts** — consumes `databaseOperationDuration` for DB client instrumentation.
- **metrics-queue.ts** — consumes `queueJobsDeadLetteredTotal`.
- **metrics-rate-limit.ts** — consumes `rateLimitStoreFallbackTotal` and `rateLimitRefusalsTotal`.
- **metrics-process.ts** — consumes `processUnhandledRejectionsTotal`, `processUptimeSeconds`, `nodejsHeapSizeLimitBytes`, `jobLastSuccessTimestampSeconds`, `jobLastRunTimestampSeconds`.
- **metrics-registry.ts** — registers all definitions from `infrastructureMetricData` into the runtime metrics registry.
- **tests/cross-cutting/metric-names.test.ts** — validates that metric names and label sets conform to naming conventions.

## Notes

- **Do not edit this file by hand.** All changes go through `shared/rules/metrics.yaml`, then `npm run regenerate`.
- The `as const` assertion gives every property literal types, so downstream code gets compile-time checking on `kind`, `name`, and label names.
- Histogram buckets are fixed at generation time; adjusting them requires a YAML edit + regenerate, not a code change.
- `jobLastSuccessTimestampSeconds` and `jobLastRunTimestampSeconds` are gauges (not counters) and carry a `task` label — they represent "last known value" rather than a monotonically increasing count.
