# src/infrastructure/observability/audit.ts

## Purpose

Defines the structured audit-trail emission pipeline: the event schema (`AuditEvent` / `AuditEntry`), the app-level action constant set, and the `emitAuditEvent` / `buildAuditEvent` helpers that every module calls to record "who did what to which resource, and did it work." It is deliberately separate from application logging—audit entries are a security/compliance artefact written to a dedicated always-on `auditLogger` with a stable, machine-readable field set.

## Key elements

- **`coreAuditActions`** (re-export from `./audit-actions.generated`) — dot-notation action strings (`auth.*`, `admin.product.*`) for app-level events emitted before any domain module sees the request. Generated by `scripts/docs/generate-audit-actions.ts` from `shared/rules/audit-actions.yaml`.
- **`AuditActionMap`** — empty `interface` that each domain module augments via declaration merging (e.g. `modules/account/audit.ts`), keeping `infrastructure` free of any `@modules/*` import.
- **`AuditAction`** — union of `CoreAuditAction` and `AuditActionMap[keyof AuditActionMap]`; the exhaustive set of actions a build can emit.
- **`AUDIT_ACTOR_ROLES` / `AUDIT_OUTCOMES` / `AUDIT_LEVELS`** — `Object.values` arrays of the enum types, exposed as the schema's allowed-value lists.
- **`AuditEvent`** — the field contract for one audit record: `actorUserId`, `actorRole`, `actorRoleName?`, `actorCredentialId?`, `actorScope`, `action`, `outcome`, `ip?`, `userAgent?`, `requestId?`, `traceId?`, `targetType?`, `targetId?`, `metadata?`.
- **`AuditEntry`** — `AuditEvent` + `timestamp` + `level`, added at emit time.
- **`AuditSink`** — `(entry: AuditEntry) => void`; a port for persistence (implemented by `@modules/audit-logs/module`). Must not throw or reject.
- **`registerAuditSink(sink)`** — installs the sink; called once at module registration. Unregistered is a valid state (tests, queue workers).
- **`emitAuditEvent(event)`** — writes the log line via `auditLogger.log(level, action, event)`, then hands the entry to the registered sink inside a `try/catch` so a broken sink cannot fail the request.
- **`extractRequestContext(context)`** — pulls `ip`, `userAgent`, `requestId`, `traceId` (via `getActiveSpanContext()`) from a `CallerContext`.
- **`buildAuditEvent(context, fields)`** — combines caller context with mandatory `action` + `outcome` to produce a fully-populated `AuditEvent`; derives `actorRole` via the internal `resolveActorRole`.

## Relationships

- **`src/infrastructure/adapters/logger.ts`** — imports `auditLogger`, the dedicated always-on Winston logger that receives every audit line.
- **`src/infrastructure/observability/tracer.ts`** — imports `getActiveSpanContext()` to stamp `traceId` on each event, linking audit entries to OTel traces.
- **`scripts/docs/generate-audit-actions.ts`** — generates `./audit-actions.generated.ts`, the source of `coreAuditActions`.
- **`src/infrastructure/observability/security-events.ts`** / **`forbidden.ts`** — sibling observability files; the guard/middleware layer calls `emitAuditEvent` with the core actions these files reference.
- **`src/kernel/middlewares/authorizations.ts`** — the `requirePermissionGuard` path emits audit events and is the one caller that explicitly overrides `actorScope` for platform-key checks.
- **`src/modules/account/services/caller.ts`** — builds the `CallerContext` (`callerContextOf`) that `buildAuditEvent` and `extractRequestContext` consume.
- **`src/modules/account/services/account-deletion.ts`**, **`email-change.ts`**, **`erasure-ledger.ts`** — domain services that call `buildAuditEvent` / `emitAuditEvent` with module-specific actions from their own `AuditActionMap` augmentation.
- **`src/modules/access/services/role-audit.ts`** — augments `AuditActionMap` with access-domain actions and emits role-related audit events.
- **`src/infrastructure/http/middlewares/origin.ts`**, **`rate-limit.ts`** — emit audit events (via core actions) for requests refused before any domain handler runs.

## Notes

- **Declaration-merging seam:** `AuditActionMap` is intentionally empty. Adding a new domain action requires augmenting this interface in the module's own `audit.ts`; `infrastructure` never imports from a module.
- **`actorScope` gotcha:** `context.caller` is always resolved in tenant scope. Platform-key rejections must be passed an explicit `actorScope` override (done by `requirePermissionGuard`); otherwise a platform refusal is mis-recorded as tenant.
- **`resolveActorRole` ordering:** `SYSTEM_ACTOR` is checked *before* `unrestricted` because a system actor is also unrestricted—without that ordering every background job reads as `admin`.
- **Sink contract:** `registerAuditSink` runs on the request path (module registration), so the sink must be fire-and-forget. `emitAuditEvent` wraps the sink call in `try/catch` as a second layer of protection; a throwing sink logs `audit.sink.failed` but never propagates.
- **`ip` fidelity:** reflects the proxy address unless Express `trust proxy` is set—behind a load balancer that setting is required for the field to be meaningful.
- **`metadata` redaction:** anything placed in `metadata` passes through the logger's redaction pipeline before hitting the wire.
