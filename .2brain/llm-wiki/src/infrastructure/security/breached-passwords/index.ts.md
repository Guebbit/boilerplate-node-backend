# src/infrastructure/security/breached-passwords/index.ts

## Purpose
Refuses breached passwords when they are being **set**: signup, password change and reset. It is never used on login, because refusing there would confirm a guess to an attacker and lock out the user the check is meant to protect. There are two independent rungs. Rung 1 is a bundled list of common breached passwords. Rung 2 is the HIBP k-anonymity range API. Both fail open. A strength meter ("rung 3") exists only in the frontend and is not enforced here.

## Key elements
- `bundledList` (private): a `Set` read synchronously at import time from `breached-passwords.txt` in `SHARED_RULES_DIRECTORY`. The file is shared byte-for-byte with the PHP twin and generated by `scripts/security/refresh-breached-passwords.ts`. Matching is exact and case-sensitive.
- `isInBundledBreachList(password)`: rung 1. It is a synchronous set lookup with no network.
- `checkHibpRange(password)`: rung 2.
  - It SHA-1 hashes the password and sends only the 5-hex-char prefix to `https://api.pwnedpasswords.com/range/<prefix>`, with `Add-Padding: true`.
  - It matches the suffix locally and ignores padding entries, which have count 0.
  - It uses `AbortSignal.timeout` from config, `redirect: 'error'`, and a capped body read.
  - On any failure it logs a warning and returns `{ breached: false }`.
  - It resolves to `{ breached, count? }`.
- `checkPasswordBreach(password)`: combines both rungs. Rung 1 runs only if `NODE_PASSWORD_BREACH_LIST` is on, and a hit short-circuits. Rung 2 runs only if `NODE_PASSWORD_BREACH_HIBP` is on. It is the only path that exposes `count`, which the advisory endpoint reads.
- `assertPasswordNotBreached(password)`: the check that password-set paths call. It returns a `ResponseErrorItem[]`, which is empty if the password is acceptable. Otherwise it holds one `fieldError('password', t('validation.password-breached'))`. The message never says which rung matched.

## Notes
- Both rungs fail open. An HIBP outage logs a warning and the password is accepted.
- The bundled list loads at import time with `readFileSync`, so a missing file fails the import. The list is about 20k entries.
- Only the SHA-1 prefix leaves the process, so HIBP never learns the password or whether it matched.
- The `Stryker disable` comments around the log call exclude it from mutation testing.
