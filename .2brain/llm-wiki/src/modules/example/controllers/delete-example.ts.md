# src/modules/example/controllers/delete-example.ts

## Purpose

Handles `DELETE /examples/:id` by validating the id, delegating the permanent removal to `exampleService.remove`, and shaping the HTTP response. It is hand-written (rather than generated by the shared delete factory) because this module has only a single hard-delete tier and no soft-delete flag to manage.

## Key elements

- **`deleteExample`** (exported) – Express handler. Validates the `:id` param via `requireId`, calls `exampleService.remove(id, callerContextOf(request))`, then either short-circuits via `refused` (e.g. 404 for missing/forbidden) or sends `successResponse` with `200` and the service-provided `result.message`. Errors are funneled to `catchAs`.

## Relationships

- **`src/modules/example/services/index.ts`** – imports `exampleService`; its `remove` method performs the actual deletion and returns a result the controller inspects.
- **`src/modules/example/routes.ts`** – registers `deleteExample` as the handler for the `DELETE /examples/:id` route.
- **`src/infrastructure/http/ids.ts`** – `requireId` extracts and validates the `:id` param; returns `undefined` (and sends 404) when the id is malformed or unknown.
- **`src/infrastructure/http/request.ts`** – `callerContextOf` pulls the authenticated caller context out of the request to pass to the service.
- **`src/infrastructure/http/response.ts`** – `successResponse` serialises the 200 body.
- **`src/infrastructure/http/controller.ts`** – `refused` inspects the service result and short-circuits with the appropriate error status; `catchAs` maps thrown errors to an HTTP error response.

## Notes

- All failure modes (malformed id, unknown id, caller not permitted) collapse to **404** — there is no 403 path.
- Success is **200** with a JSON body (`result.message`), not 204 No Content.
- The doc comment references `docs/theory/request-flow.md` for the broader request lifecycle.
