# src/modules/payments/tests/unit/display-status.test.ts

## Purpose

Unit tests for the `displayStatusOf` domain function, verifying that a payment's display label is derived correctly from its stored status, open/settled/failed/canceled refunds, and the `amountRefunded` figure. The file pins the precedence rule (an open refund overrides the stored status) and the minor-unit comparison for "fully refunded" detection.

## Key elements

- **`describe('displayStatusOf')`** – top-level suite; defines shared fixtures (`open`, `failed`, `settled`, `canceled` refund arrays and a `base` payment object).
- **`it.each` table (14 cases)** – parametrized over `[PaymentStatus, refunds[], amountRefunded, expected PaymentDisplayStatus]`. Covers: incomplete/pending/succeeded/failed/cancelled base statuses; partial vs. full refund; multiple settled refunds; an open or failed refund overriding to `refund_pending`; a `canceled` refund (staff-voided) NOT overriding; and mixed refund lists.
- **`it('compares the amounts in minor units…')`** – asserts that `amountRefunded: 0.1 + 0.2` still reads as `refunded` against `amount: 0.3`, guarding against floating-point drift in the comparison logic.

## Relationships

- **`src/modules/payments/domain/display-status.ts`** – the implementation under test; `displayStatusOf` is the sole function exercised here.

- **`src/types/index.ts`** – source of the `PaymentStatus`, `RefundStatus`, `RefundFailureReason`, and `PaymentDisplayStatus` types used to type the fixtures and test table.

## Notes

- The `canceled` fixture (`failed` + `RefundFailureReason.canceled`) is intentionally distinct from a generic `failed` refund: a staff-voided refund is treated as *closed*, so it does not trigger the "open refund wins" path. The test asserts it falls through to the stored status.
- Amounts in the `base` fixture are integer cent-like values (50, 0); the float test uses decimal values to ensure the domain code compares in minor units rather than raw floats.
- Test naming follows the pattern `reads <status> with refunds <json> and <n> refunded as <display>`, generated by `it.each` interpolation — useful for grep'ing a specific scenario in CI output.
