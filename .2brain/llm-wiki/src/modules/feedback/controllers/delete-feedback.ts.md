# src/modules/feedback/controllers/delete-feedback.ts

## Purpose

Controller for `DELETE /feedback/:id`. Permanently removes a feedback ticket via `feedbackRequestService.remove`. Hand-written rather than built on the shared `createDeleteController` factory because the feedback module has no soft-delete tier.

## Key elements

- **`deleteFeedback`** (exported) — The sole export. Accepts Express `Request<{ id: string }>` and `Response`. Calls `feedbackRequestService.remove(id, callerContextOf(request))`, then either:
    - short-circuits with a permission `refused` response, or
    - sends a 200 via `successResponse` with the service's `result.message`.
    - Catches errors via `catchAsNotFound`, mapping failures to 404.

## Relationships

- **`src/infrastructure/http/response.ts`** — imports `successResponse` to build the 200 reply.
- **`src/infrastructure/http/request.ts`** — imports `callerContextOf` to extract caller context from the request for the service call.
- **`src/infrastructure/http/controller.ts`** — imports `catchAsNotFound` (error → 404) and `refused` (permission denial check).
- **`src/modules/feedback/service.ts`** — imports `feedbackRequestService`; the `.remove()` method performs the actual deletion.
- **`src/modules/feedback/routes.ts`** — registers this controller on the `DELETE /feedback/:id` route.

## Notes

- A malformed or unknown `:id` intentionally returns **404**, not the generic 422 the shared database-error interpreter would produce for a bad `ObjectId`. This mirrors the `CastError` handling in `createDeleteController`.
- The comment explicitly states this file is _not_ generated by `createDeleteController` (which serves the soft/hard-delete triplet); the feedback module has no soft-delete tier, so the factory is inapplicable.
