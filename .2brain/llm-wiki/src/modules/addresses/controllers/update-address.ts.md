# src/modules/addresses/controllers/update-address.ts

## Purpose
Defines the HTTP controllers for `PUT /account/addresses/:addressId` (replace) and `PATCH /account/addresses/:addressId` (merge). Both are generated by the shared `createUpdateController` factory and delegate to `addressService.update`.

## Key elements
- `replaceAddress` — the `PUT` handler. It validates the body with `ReplaceAddressBody`.
- `updateAddress` — the `PATCH` handler. It validates the body with `UpdateAddressBody`.
- Factory configuration:
  - `versioned: false` — no `If-Match` handling.
  - `entity: 'address'`.
  - `idParam: 'addressId'` — the route param is `:addressId`, not the factory's default `:id`.
  - `notFoundKey: 'addresses.not-found'`.
  - `update` — calls `addressService.update(request.authContext!.id, id, changes)`, so the caller's auth id is the owner scope.
  - `present: (view) => view` — returns the service result unchanged.

## Relationships
- `src/infrastructure/surfaces/create-update-controller.ts` — supplies the `createUpdateController` factory that builds both handlers.
- `src/modules/addresses/service.ts` — exports `addressService`, whose `update` method performs the write, checks ownership, and returns the entry it wrote.
- `src/modules/addresses/routes.ts` — a graph neighbor of this file. That is presumably where `replaceAddress` and `updateAddress` are wired to the `PUT` and `PATCH` routes, but the file content here doesn't show it.

## Notes
- An address the caller doesn't own returns the same 404 as one that doesn't exist. Ownership is checked in the service, and a distinguishable response would reveal that the id belongs to someone else.
- There is no optimistic concurrency (`If-Match`). The address lives in one book document with a single owner, so a book-level counter would make an edit to address A refuse an edit to address B.
- `request.authContext!` is non-null asserted, so the handlers assume authentication middleware has already run.
