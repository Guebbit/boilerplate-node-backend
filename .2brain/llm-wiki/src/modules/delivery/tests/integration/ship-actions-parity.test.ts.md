# src/modules/delivery/tests/integration/ship-actions-parity.test.ts

## Purpose

Integration test that verifies the `ship` boolean exposed on a fulfillment order's actions always agrees with whether the actual `POST …/shipments` endpoint accepts the request (a 2xx response). It sweeps every combination of staff role × order status to catch any divergence between the read-model flag and the write-path authorization.

## Key elements

- **`ROLES`** — Tuple of four staff roles (`admin`, `manager`, `warehouse`, `support`) that differ in `start:Shipment` / `update:Shipment` permissions.
- **`STATUSES`** — Tuple of the four order statuses under test: `pending`, `paid`, `processing`, `canceled`.
- **`accepted`** — Small helper returning `true` for 2xx HTTP status codes.
- **Single test (`for every role and every status`)** — Loops over the full matrix, creates a fresh product + order per cell, forces the target status, reads the `ship` flag via `GET /orders/:id/fulfillment-orders`, then attempts `POST /delivery/fulfillment-orders/:id/shipments`. Collects any `opened !== ship` mismatches and asserts the list is empty.
- **`shippedFromPaid` counter** — Asserted to equal 2, guaranteeing that at least `admin` and `warehouse` successfully ship from `paid` (prevents a vacuous all-rejected pass).

## Relationships

- **`tests/support/setup-test-db.ts`** — Called at module scope (`setupTestDb()`) to prepare the test database before any test runs.
- **`tests/support/checkout-modules.ts`** — `registerCheckoutModules([])` in `beforeEach` resets module registrations between tests.
- **`tests/support/http.ts`** — Provides `api()` (supertest wrapper) and `authenticateAsRole` for issuing authenticated requests as each role.
- **`src/modules/products/tests/factories.ts`** — `createProduct` builds the product needed for each order.
- **`src/modules/orders/tests/factories.ts`** — `createOrder` and `toOrderItem` build the order; `forceOrderStatus` transitions the order to the target status after creation.
- **`src/modules/delivery/tests/factories.ts`** — `fulfillmentOrdersOf` retrieves the fulfillment order ID generated by the paid order's creation.
- **`src/types/index.ts`** — Supplies the `OrderStatus` enum values and the `FulfillmentOrder` type used to type the API response body.

## Notes

- Orders are always created with status `paid` first (so fulfillment orders exist), then forced to the target status. This means even `pending` and `canceled` orders carry a fulfillment order, per the inline comment.
- Each matrix cell gets its own order because the ship endpoint mutates state ("the door writes"), so cells cannot share an order.
- The test is a single `it` block performing the full sweep rather than using `it.each` / parameterization; disagreements are accumulated and asserted once at the end.
