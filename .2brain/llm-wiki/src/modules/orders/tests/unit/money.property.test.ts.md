# src/modules/orders/tests/unit/money.property.test.ts

## Purpose

Property-based tests for the `Money` domain module. The invariant under test is that **no** monetary function can ever produce `NaN`, `Infinity`, or a fractional cent, regardless of input. Arbitraries are deliberately hostile (junk strings, booleans, `undefined`, overflow values) rather than realistic, and the suite is seeded so any counterexample is reproducible and can be pinned as a plain `it()` case.

## Key elements

- **`RUN`** – Single-file configuration: seed `20260819`, run count from `PROPERTY_RUNS` (imported from knobs), `endOnFailure: true`. Change the seed here and only here.
- **`anything()`** – Arbitrary that mixes `fc.double`, `fc.integer`, `fc.string`, `fc.boolean`, `null`, `undefined`, `Number.MAX_VALUE`, and `'1e400'`. Simulates malformed documents, hostile clients, or failed populates.
- **`realisticPrice()`** – Bounded non-negative, non-NaN double (0 … 1e6). The "realistic half" of the input space.
- **`money()`** – Arbitrary integer of minor units (0 … 10 000 000) mapped through `toMinorUnits`, producing a branded `Money` value.
- **`describe` blocks** – One per exported function from `money.ts` (`toMinorUnits`, `toDecimalAmount`, `addMoney`, `scaleMoney`, `wholeCount`, `subtractMoney`, `scaleMoneyByRate`, `apportion`), plus a round-trip block for the pair `toMinorUnits` ↔ `toDecimalAmount`.
- **`NO_MONEY`** – Imported sentinel for "nothing owed"; used both as an expected value and as an identity element in `addMoney` tests.

## Relationships

- **`src/modules/orders/domain/money.ts`** – The sole module under test. Every function under test (`addMoney`, `apportion`, `scaleMoney`, `scaleMoneyByRate`, `subtractMoney`, `toDecimalAmount`, `toMinorUnits`, `wholeCount`) and the `NO_MONEY` constant are imported directly from here.
- **`tests/support/knobs.ts`** – Supplies `PROPERTY_RUNS`, the shared run-count for all `fc.assert` calls in this file, so the count is tuned in one place across the test suite.

## Notes

- The `RUN` object is typed `as const`; do not replace it with a per-test config unless you have a specific reason.
- `money()` uses `.map((n) => toMinorUnits(n / 100))` because `Money` is a **brand**, not a constructible type — you cannot `new` it, you must go through the domain's own constructor.
- The `scaleMoneyByRate` block includes a **hard-coded regression** (`19.9 × 0.22/1.22 === 359`) that pins a specific float-dust case flagged in `VAT.md`; it is not generated by `fast-check`.
- The `apportion` "all-zero weights" and "empty weights" cases are plain `it()` assertions, not property tests, because the edge cases are finite and enumerated.
- See `docs/theory/tactical-ddd.md` §3 for the design rationale behind the totality contract these tests enforce.
