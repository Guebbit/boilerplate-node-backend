# src/modules/api-keys/controllers/revoke-api-key.ts

## Purpose

Handler for `DELETE /api-keys/:id`. Revoking an API key is a state change (not a soft/hard delete), so this controller is hand-written rather than generated by `createDeleteController`. It validates the id, delegates to the API-keys service, and translates the result into an HTTP response.

## Key elements

- **`revokeApiKey`** (exported) — The sole export. Accepts an Express `Request<{ id: string }>` and `Response`. Flow: validate id via `requireId` → call `apiKeysService.revokeApiKey(id, tenantCallerContextOf(request))` → on success send `204 No Content` (via `noContentResponse`); on a "refused" result short-circuit via `refused()`; on thrown error map it with `catchAs`.

## Relationships

- **`../services/index.ts`** — Calls `apiKeysService.revokeApiKey(id, context)`; the service owns the actual state transition and returns a result the controller inspects.
- **`@infrastructure/http/controller.ts`** — Provides `catchAs` (maps thrown errors to an HTTP error response, tagged `'revokeApiKey'`) and `refused` (checks whether the service result signals rejection and writes the corresponding response).
- **`@infrastructure/http/ids.ts`** — `requireId` validates the `:id` param; a malformed id produces a generic `404` (`'generic.error-item-gone'`) without touching the database.
- **`@infrastructure/http/request.ts`** — `tenantCallerContextOf` extracts the tenant/caller context from the request and passes it to the service.
- **`@infrastructure/http/response.ts`** — `noContentResponse` writes the `204` body/headers on success.
- **`src/modules/api-keys/routes.ts`** — Registers `revokeApiKey` as the handler for `DELETE /api-keys/:id`.

## Notes

- **Idempotent by design:** revoking an already-revoked key still returns `200`/`204` rather than an error.
- **Not a delete:** Despite using `DELETE` semantics on the route, the operation is a state change with no hard-delete counterpart. The doc comment explicitly calls out why `createDeleteController` was not used.
- **Validation before I/O:** `requireId` short-circuits with a generic 404 for malformed ids, so the database is never queried with garbage.
- The route uses `DELETE` but the response on success is `204 No Content` (no body), not `200`.
