# src/modules/api-keys/controllers/revoke-api-key.ts

## Purpose

Hand-written controller that handles `DELETE /api-keys/:id` by revoking a credential (a soft state change). It exists as a standalone function rather than being generated by the `createDeleteController` factory because revoke has no hard-delete counterpart — it is purely an idempotent state transition.

## Key elements

- **`revokeApiKey(request, response)`** — The sole export. Validates the `:id` param, calls `apiKeysService.revokeApiKey` with the tenant/caller context, and responds 200 with a message on success or a "refused" status on denial. Idempotent: revoking an already-revoked key still returns 200.

## Relationships

- **`src/infrastructure/http/ids.ts`** — Imports `requireId` to parse and validate the `:id` route param; a malformed id short-circuits with a generic 404 before any service call.
- **`src/infrastructure/http/request.ts`** — Imports `tenantCallerContextOf` to extract the authenticated tenant/caller context passed into the service.
- **`src/infrastructure/http/response.ts`** — Imports `successResponse` to emit the 200 JSON body.
- **`src/infrastructure/http/controller.ts`** — Imports `catchAs` (unified error serialization keyed to `'revokeApiKey'`) and `refused` (intercepts a denial result before the success path).
- **`src/modules/api-keys/services/index.ts`** — Imports `apiKeysService` and calls its `revokeApiKey(id, context)` method; this is the only business-logic interaction.
- **`src/modules/api-keys/routes.ts`** — Imports `revokeApiKey` and binds it to the `DELETE /api-keys/:id` route.

## Notes

- The file doc-comment explicitly states *why* this is hand-written rather than factory-generated: the `createDeleteController` factory is scoped to a soft/hard-delete triplet, and revoke doesn't fit that shape. Do not refactor it into the factory without rethinking the triplet contract.
- `requireId` with `{ notFound: 'generic.error-not-found' }` means a structurally invalid UUID (wrong length, bad chars, etc.) is indistinguishable to the client from a genuinely missing key — an intentional information-leak mitigation.
