# src/modules/invoicing/jobs.generated.ts

## Purpose

Generated data file that declares the invoicing module's scheduled jobs (name, cron schedule, human-readable summary) as a frozen object. It is produced from `src/modules/invoicing/module.yaml` by `npm run regenerate` and serves as the single source of job metadata consumed at runtime by `jobs.ts`.

## Key elements

- **`invoicingJobData`** (exported const, `as const`) — a plain object whose keys are job identifiers and whose values carry `name` (CLI-style label), `schedule` (5-field cron), and `summary` (one-line description). Currently contains:
  - `reapInvoicePdfs` — cron `8 2 * * *`; deletes stored invoice/credit-note PDFs past their retention window.
  - `reapInvoices` — cron `14 2 * * *`; blanks a buyer block once tax retention ends and deletes the cached PDF.

## Relationships

- **`src/modules/invoicing/jobs.ts`** — the sole consumer. `jobs.ts` imports `invoicingJobData` to attach handler functions and register the jobs with the scheduler; this file provides the declarative metadata only.

## Notes

- **Do not edit this file by hand.** All changes must be made in `src/modules/invoicing/module.yaml` and then `npm run regenerate` re-emitted the file.
- The `as const` assertion means keys and string values are literal types; any consumer (e.g. `jobs.ts`) that maps over `invoicingJobData` will get a closed union of known job IDs at compile time.
- The file deliberately contains *no* logic or imports — it is pure data so it can be tree-shaken or inlined without side effects.
