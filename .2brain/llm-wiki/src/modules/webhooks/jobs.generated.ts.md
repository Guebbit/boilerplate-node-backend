# src/modules/webhooks/jobs.generated.ts

## Purpose

Generated data file that declares the scheduled jobs for the webhooks module as a plain object (`webhooksJobData`). It exists so job metadata (name, cron schedule, summary) lives in a single machine-generated artifact produced from `module.yaml`, keeping the schedule definition separate from the execution logic in `jobs.ts`.

## Key elements

- **`webhooksJobData`** (exported `const`) — A read-only record mapping job identifiers to their metadata. Currently contains:
  - `sweepWebhookRetries` — cron `* * * * *` (every minute); re-enqueues a webhook delivery whose `nextAttemptAt` has elapsed (the delayed-retry half of the retry story).

## Relationships

- **`src/modules/webhooks/jobs.ts`** — Consumes `webhooksJobData` to wire up each declared job with its actual execution handler. This file provides *what* runs and *when*; `jobs.ts` provides *how* it runs.

## Notes

- **Do not edit by hand.** The file header states it is regenerated by `npm run regenerate` from `src/modules/webhooks/module.yaml`. Any change to job names, schedules, or summaries must be made in the YAML source, then the file re-generated.
- The `as const` assertion makes the object deeply readonly; TypeScript will reject any mutation attempts at compile time.
- Adding a new job means adding an entry in `module.yaml` and re-running the generator — you never add to this file directly.
