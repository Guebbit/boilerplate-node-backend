# src/modules/webhooks/controllers/delete-subscription.ts

## Purpose

Express controller handler for `DELETE /webhooks/subscriptions/:id`. It permanently removes a webhook subscription (leaving its delivery log intact). It is hand-written rather than built on `createDeleteController` because that factory is designed for a soft/hard delete triplet, and this module only has a single permanent delete.

## Key elements

- **`deleteWebhookSubscription`** (exported) — The sole handler. Validates the `:id` param, calls `webhooksService.removeSubscription(id, tenantContext)`, returns **204 No Content** on success or a refused/error response. A malformed id short-circuits as a generic "item-gone" 404 before any database call.

## Relationships

- **`src/infrastructure/http/controller.ts`** — provides `catchAs` (unified error-to-response mapping) and `refused` (checks whether the service returned a refusal that should be sent back to the caller).
- **`src/infrastructure/http/ids.ts`** — provides `requireId`, which parses and validates the `:id` route parameter.
- **`src/infrastructure/http/request.ts`** — provides `tenantCallerContextOf`, used to derive the caller's tenant scope for the service call.
- **`src/infrastructure/http/response.ts`** — provides `noContentResponse`, the 204 helper used on successful deletion.
- **`src/modules/webhooks/services/index.ts`** — source of `webhooksService`, whose `removeSubscription` method performs the actual delete.
- **`src/modules/webhooks/routes.ts`** — the route table that registers this handler under the DELETE path.

## Notes

- The file is intentionally **not** generated by `createDeleteController`; adding a soft-delete variant would mean switching to the factory, not extending this file.
- A malformed (non-UUID) `id` is answered as a generic 404 (`generic.error-item-gone`) so the API does not leak whether a given id format is valid.
- The delivery log associated with the subscription is deliberately **not** cascade-deleted; this is a product decision, not an oversight.
