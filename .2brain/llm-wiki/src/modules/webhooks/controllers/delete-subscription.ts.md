# src/modules/webhooks/controllers/delete-subscription.ts

## Purpose

Controller handler for `DELETE /webhooks/subscriptions/:id`. It permanently removes a webhook subscription (its delivery log remains untouched). It is hand-written rather than generated by `createDeleteController` because the webhooks module defines only a single permanent-delete endpoint, not the soft/hard delete triplet that factory targets.

## Key elements

- **`deleteWebhookSubscription(request, response)`** (exported) — The sole handler. Validates the `:id` param, enforces an `If-Match` precondition, delegates to `webhooksService.removeSubscription`, and responds **204 No Content** on success.
- **`requireId`** — Parses and validates the route param before any DB access; a malformed id short-circuits to a generic 404 (`generic.error-item-gone`).
- **`withIfMatch`** — Wraps the service call in optimistic-concurrency fencing; a stale `If-Match` tag yields **412 Precondition Failed**. The resource is `x-versioned`.
- **`refused` / `catchAs`** — Standard controller error-handling pair: `refused` inspects a result object for a 4xx-level rejection; `catchAs` maps thrown exceptions to an appropriate error response and logs under the `deleteWebhookSubscription` tag.

## Notes

- The comment explicitly states the delivery log is **not** deleted; do not assume cascading removal.
- The `If-Match` check is mandatory for this endpoint (it is `x-versioned`), so clients that omit the header will be rejected.
- The 404 for a malformed id uses the generic `error-item-gone` code intentionally, to avoid leaking that the id format was wrong vs. truly missing.
