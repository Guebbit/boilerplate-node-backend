# src/modules/webhooks/controllers/delete-subscription.ts

## Purpose
Hand-written controller for `DELETE /webhooks/subscriptions/:id`. It permanently removes a webhook subscription (the delivery log is intentionally left in place). It exists as a standalone function rather than a product of `createDeleteController` because the webhooks module has only a permanent delete, not the soft/hard delete triplet that factory targets.

## Key elements
- **`deleteWebhookSubscription(request, response)`** — the sole export. Validates the `:id` param via `requireId`, delegates to `webhooksService.removeSubscription(id, tenantCallerContext)`, returns `204 No Content` on success, and funnels rejections through `refused` / `catchAs`.

## Relationships
- **`src/infrastructure/http/controller.ts`** — supplies `catchAs` (uniform error formatting) and `refused` (short-circuits on service-level refusal).
- **`src/infrastructure/http/ids.ts`** — supplies `requireId`, which validates the path param and early-returns a 404-shaped response for malformed IDs.
- **`src/infrastructure/http/request.ts`** — supplies `tenantCallerContextOf`, which extracts the tenant-scoped caller context from the request before the service call.
- **`src/infrastructure/http/response.ts`** — supplies `noContentResponse` for the 204 reply.
- **`src/modules/webhooks/routes.ts`** — registers this handler on the `DELETE /webhooks/subscriptions/:id` route.
- **`src/modules/webhooks/services/index.ts`** — provides `webhooksService.removeSubscription(id, ctx)`, the actual deletion logic.

## Notes
- Malformed or missing IDs never reach the database: `requireId` short-circuits with the error code `generic.error-item-gone` before any service call.
- The `catchAs` tag is the string literal `'deleteWebhookSubscription'`, which is what appears in server logs / error telemetry.
- This file is explicitly *not* generated by the `createDeleteController` factory; if you see a pattern mismatch with other modules' delete controllers, that is by design.
