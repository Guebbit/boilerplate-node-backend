# src/app/jobs.generated.ts

## Purpose

Auto-generated registry of kernel job metadata (display name, cron schedule, human-readable summary) that is consumed by `src/app/jobs.ts` to wire up scheduled tasks. It exists so that job definitions live in a single YAML source of truth (`shared/rules/jobs.yaml`) and are kept in sync across the codebase via `npm run regenerate`.

## Key elements

- **`appJobData`** (exported `as const` object) — the sole export. Maps four keys (`reapQuarantine`, `reapOrphanedImages`, `reapMailSpool`, `sweepOutbox`) to objects with:
  - `name` — CLI-style identifier (e.g. `'reap:quarantine'`)
  - `schedule` — cron expression
  - `summary` — one-line description of the job's intent
- The `as const` assertion makes every property a literal type, enabling exhaustive switching in downstream code.

## Relationships

- **`src/app/jobs.ts`** — Imports `appJobData` and layers executable handlers (the actual work each job performs) on top of this metadata. The division of labor is: *this file* = "what/when", `jobs.ts` = "how".

## Notes

- **Do not edit this file.** The header comment states it is generated; all changes must go through `shared/rules/jobs.yaml` followed by `npm run regenerate`.
- All four jobs are currently scheduled in the 02:00–03:00 UTC window except `sweepOutbox`, which runs every minute as a backstop.
- The `as const` modifier means adding a new job in YAML will appear here as a new key with narrowed literal types — no runtime type annotation needed.
